# AutoCrystal integration risks

- **Target version behavior:** the reference targets a different Minecraft version. Confirm damage, collision, placement, and packet behavior in 1.21.5.
- **Target selection:** friend names are persisted and excluded from the nearest-player selection. Multi-target damage aggregation is not ported; the reference cycle selects one nearest eligible target for this path.
- **Anti-phase and mining sync:** the v2 JNI snapshot supplies collision-backed phase blocks. Vanilla block breaking now publishes its active block and progress to `MiningSyncState`, which applies the ownership and 0.85 progress gates. Xing still has no PacketMine or AutoMine modules, so packet-mining ownership and the AutoMine-specific score boost are unavailable.
- **Spawn-reactive breaks:** a matching spawn clears the pending placement immediately, then asks the native planner to validate that crystal and plan its replacement. Attacks use the shared packet interaction adapter.
- **Shared managers (uint32):** native `SlotSpoofManager` and `RotationManager` own priority, ownership, restore timing, aim calculation, and rotation holds. `XingClient.managers` provides reusable inventory, network, rotation, and interaction adapters. AutoCrystal uses sequenced packet placement with CLIENT swaps, matching the reference defaults; the inventory adapter also supports SILENT and NONE modes.
- **Combat scheduling:** native resource leases, channel limits, queued priorities, dependencies, cancellation, and packet commit tracking are integrated through the shared managers. Immediate breaks preserve Synthetic's resource-only exception to the ordinary attack limit. AutoCrystal still executes its current immediate cycle; staged module actions and the reference's separate crystal command-token lifecycle are not integrated with this scheduler.
- **Packet commits:** commit IDs, owner identity, and prediction sequences are reported at the outgoing dispatch boundary, matching the reference connection mixin. Commit does not mean successful socket write or server acceptance. Late reports are ignored after session changes.
- **Server state and predictions (uint32):** native trackers now store committed slot selection, inventory hand snapshots, container revisions, crystal spawns, and block prediction outcomes. Packet and world reset hooks are registered. Prediction creation is available through the shared ledger; AutoCrystal's existing placement guard has not been replaced by it.
- **Combat activity and slot transactions (uint32):** native activity windows and reusable silent slot transactions are integrated. Packet generations and phases distinguish swap, action, and restore commits. Higher-priority callers wait for an existing silent restore to commit before acquiring the slot. PacketMine's mining lifecycle and block-confirmed tool restoration policy remain to be ported.
- **Profile limits:** default shared channel limits are ported. Anticheat-specific policy selection remains unported; the rate adapter accepts future profile limits.
- **Rotation features:** outgoing movement respects the active native rotation, expiry restores the camera's server rotation, and server corrections clear the request. Client-side camera rotation, movement correction, and silent-sync telemetry from the reference remain unported.
- **Same-tick replacement:** both native placement scanning and final Java geometry validation ignore the successfully attacked crystal during that tick. Other entities continue to block placement. Confirm packet ordering against the target server.
- **Snapshot allocation:** the direct-buffer cache grows as needed and passes an exact-capacity slice to JNI. Compare in-game frame time before drawing conclusions about remaining planner cost.
- **Placement snapshot range:** collision boxes are sampled around the local player and selected target. Compare edge cases at the maximum damage/ray range.
- **Lifecycle parity:** pending placement and break retries have a small Java-side guard; compare timeout behavior with the reference controller.
- **End-to-end parity:** Java and native compile; verify damage scores, phase candidates, and action outcomes in-game before relying on this port.
- **DLL packaging:** the loader prefers the optimized Release DLL, with Debug as fallback. An explicit `xing.native.path` overrides that choice. Restart Minecraft after recompiling a loaded DLL.
