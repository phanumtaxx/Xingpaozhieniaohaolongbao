# MaceKill (experimental)

Enable **Combat → MaceKill** while standing on a solid block with a mace and at least five wind charges in the hotbar. Close the ClickGUI to start. Right-click the module to configure charges, shot interval, movement-packet interval, capture height, minimum fall, hold timeout and optional auto attack. Timing changes apply to the next attempt. Use the normal module keybind field for a quick cancel/restart key.

One activation performs one attempt: send downward wind charges, wait for their server-reported explosion impulses, release the accumulated local velocity, track ascent/descent, and hold near the ground. The action bar displays progress. Manual attacks remain available. Auto attack defaults off; when enabled it attacks one visible nearby player with the mace, excluding friends, teammates and spectators. Re-enable for another attempt. Stop Auto Crystal before starting to avoid competing slot and rotation changes.

The hold is explicitly **estimated**. This is an experimental implementation, not a verified reproduction of Grim Client's Air Stuck or a verified GrimAC bypass. The client cannot read authoritative server fall distance or promise stored damage, a one-hit kill, or protection against kicks. Testing the actual exploit requires the target server's version/configuration and a cooperating target. The current implementation accepts self-charge explosion packets; a server using different knockback delivery will time out rather than invent a boost.

Only local movement ticks and the normal movement-packet sender are held. Rendering, attacks, item use, keepalives and teleport confirmations continue. There are no sleeps, delayed packet queues, forged fall-distance values, or forced server teleport positions. A nearby downward correction is accepted only while already holding and only if the player's collision box remains clear with a gap above the ground. The module stops on damage, external knockback while airborne/holding, ground contact, unsupported movement, world/player changes, other menus, loss of window focus or timeout. A running attempt never resumes automatically on login. Local hotbar selection and the charge's downward pitch are restored on cancellation.

Validation: `gradlew.bat test --tests '*Mace*'` for state/settings checks; `gradlew.bat runClient -PmaceSmoke` for the isolated development-world integration check. Neither is a GrimAC compatibility test.

Stage transitions and cancellation reasons appear under `xingclient-mace` in `run/logs/latest.log`. The native DLL was also rebuilt with Microsoft's `_DISABLE_CONSTEXPR_MUTEX_CONSTRUCTOR` compatibility option: the installed JDK 21 bundles an older C++ runtime that crashed when the imported DLL initialized its inventory tracker. See the [Microsoft STL release notes](https://github.com/microsoft/STL/releases/tag/vs-2022-17.10). The original DLL is backed up locally in `.qa/xing-before-mace.dll`.
